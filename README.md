# Project104. Eurochip I / Eurochip II authentication reconstruction

One more masterpiece.

Independent reconstruction of the authentication algorithm used in Siemens/Infineon SLE4436 (Eurochip I) and SLE5536 (Eurochip II) telephone cards.

The Eurochip I reconstruction corresponds to the architecture described in EP0624839B1. The implementation also supports the second authentication key and the CBC behavior used by Eurochip II.

To perform authentication, you need the master key value, which is normally kept secret by the card issuer. You also need the LFSR feedback tap positions, nonlinear-function tap positions, and counter modulus values.

## Files

* `response_generator.py` — the implementation core.
* `example_usage.py` — minimal example using a card dump, derived `Kc`, and fixed challenges.
* `auth_checker.py` — compares responses produced by a physical card with responses generated by the reconstructed algorithm. It is written for the ACS ACR38 CCID memory-card interface.
* `auth_unit_structure_demo.py` — template for the algorithm parameters. Copy it to `auth_unit_structure.py` and replace the demonstration values with the actual ones.
* `secret_demo.py` — template for the master key. Copy it to `secret.py` and replace the demonstration value with the actual one.

## Requirements

Python 3 is required.

Install the Python dependencies with:

```bash
python -m pip install -r requirements.txt
```

`auth_checker.py` additionally requires an ACS ACR38 reader, or a compatible reader implementing the same memory-card pseudo-APDUs.

## Configuration

Create the local configuration files:

```bash
cp secret_demo.py secret.py
cp auth_unit_structure_demo.py auth_unit_structure.py
```

On Windows:

```cmd
copy secret_demo.py secret.py
copy auth_unit_structure_demo.py auth_unit_structure.py
```

Then edit `auth_unit_structure.py` and `secret.py` and fill in the actual values:

* LFSR feedback taps;
* nonlinear-function taps;
* counter modulus values;
* master key.

Tap numbers in the public API use physical register-cell numbering. For a 47-cell register, both linear and nonlinear taps are numbered `1..47`.

`secret.py` may contain provider-specific confidential material and should not be committed to a public repository.

## Usage

Run the software-only example:

```bash
python example_usage.py
```

The example constructs the algorithm input from a 16-byte card dump, a 6-byte value derived from the master key, and a 6-byte challenge. It demonstrates repeated CBC authentication calls and prints the generated two-byte responses.

To compare the reconstruction against a physical card through an ACR38 CCID reader:

```bash
python auth_checker.py
```

The checker generates random 6-byte challenges, obtains the card response, generates the corresponding response locally, and compares the two results.

## Implementation notes

The reconstruction is represented as two stages:

1. **Feed phase** — a key-dependent seed bit (`1` for KEY1, `0` for KEY2) is clocked into the register, followed by the input data LSB-first within each byte. In CBC mode, the register state is preserved between consecutive authentications and nonlinear feedback is enabled during this phase.
2. **Emit phase** — the register is clocked with zero input while the nonlinear function, latch counter, and response-bit counter generate the authentication response.

The complete input block is referred to as `DATA`. The challenge is only one field within this block; it is not synonymous with the whole input.

Responses are returned as `bytes`. Response bits are packed in chronological order, LSB-first inside each byte, so no additional output-side bit reversal is required.
