# Project104. SLE4436 / Eurochip authentication reconstruction

One more masterpiece.

Independent reconstruction of the authentication algorithm used in Siemens/Infineon SLE4436, aka Eurochip telephone cards. The SLE4436 belongs to the Type 104 card family. The implementation corresponds to the architecture described in EP0624839B1.

The code is documented inline.

To perform authentication, you need the master key value, which is normally kept secret by the card issuer. You also need the LFSR feedback tap positions, nonlinear-function tap positions, and counter modulus values.

## Files

- `response_generator.py` — implementation of the reconstructed challenge-response algorithm.
- `example_usage.py` — minimal example using a card dump, derived `Kc`, and a fixed challenge.
- `auth_checker.py` — compares responses produced by a physical SLE4436-compatible card with responses generated by the reconstructed algorithm. It is written for the ACS ACR38 CCID memory-card interface.
- `secret_demo.py` — template for the algorithm parameters and master key. Copy it to `secret.py` and replace the demonstration values with the actual ones.

## Requirements

Python 3 is required.

Install the Python dependencies with:

```bash
python -m pip install pycryptodomex pyscard
```

`auth_checker.py` additionally requires an ACS ACR38 reader, or a compatible reader implementing the same memory-card pseudo-APDUs.

## Configuration

Create the local configuration file:

```bash
cp secret_demo.py secret.py
```

On Windows:

```cmd
copy secret_demo.py secret.py
```

Then edit `secret.py` and fill in the actual values:

- LFSR feedback taps;
- nonlinear-function taps;
- counter modulus values;
- master key.

Tap numbers in the public API use physical register-cell numbering. For a 47-cell register, both linear and nonlinear taps are numbered `1..47`.

`secret.py` may contain provider-specific confidential material and should not be committed to a public repository.

## Usage

Run the software-only example:

```bash
python example_usage.py
```

The example constructs the algorithm input from the first 16 bytes of card data, a 6-byte value derived from the master key, and a 6-byte challenge, then prints the generated two-byte response.

To compare the reconstruction against a physical card through an ACR38 CCID reader:

```bash
python auth_checker.py
```

The checker generates random 6-byte challenges, obtains the card response, generates the corresponding response locally, and compares the two results.

## Implementation notes

The reconstruction is represented as two stages:

1. **Linear phase** — a leading `1` is clocked into the register, followed by the input data LSB-first within each byte.
2. **Nonlinear phase** — the register is clocked with zero input while the nonlinear function, latch counter, and response-bit counter generate the authentication response.

The complete input block is referred to as `DATA`. The challenge is only one field within this block; it is not synonymous with the whole input.

Responses are returned as `bytes`. Response bits are packed in chronological order, LSB-first inside each byte, so no additional output-side bit reversal is required.
